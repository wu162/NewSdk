# Optional spectral attenuation: 0x855ef

The complete 232-byte, 88-instruction `855ef..856d7` stage is recovered in `XmaSpectralGate.cs`. It has no callees and is an optional post-transform stage, not quantization or an XMA encoder. The channel-transform caller invokes it at 8c112 when core+18adc is enabled.

The ABI is stdcall four arguments `(core*, state*, channel*, unusedInt)`, `ret 0x10`, HRESULT zero. Core+18adc is the enable flag; state+214 is a signed integer control. Channel[0]+7c is signed short N, channel+50 points to the N-float spectrum, and channel+3c/+40 point to two 128-float band tables. Only the spectrum is written. The fourth argument is not read, and the oracle deliberately passes `deadbeef`.

Disabled operation or control >200 leaves the complete spectrum unchanged and does not dereference either band table. Otherwise factor=F32(1-control/200.0), capped above at the exact float 0.5. Original constants are double200 at d5208 (`0000000000006940`) and float0.5 at ac888 (`0000003f`). For each bin i, group=i/trunc(N/128); B=table40[group], T=F32(table3c[group]*factor). If T<B and B is nonzero, spectrum[i]=F32(((B-T)/B)*spectrum[i]); otherwise write positive zero. Subtraction, division and final multiplication retain 53-bit intermediates until the output store. Explicit physical binary32 store barriers preserve the two original FSTP rounding points in Debug/Release.

The recovered numerical domain is finite spectra with N in {128,256,512,1024,2048}, any signed control, and finite 128-entry band tables when the enabled stage actually uses them. Disabled/no-op calls permit null band tables. Candidate safety checks reject unsupported geometry and nonfinite inputs before mutation. The original negative/zero band comparisons and signed-zero outputs remain covered; generated infinities in the output are not silently clamped.

`TestAudioXmaSpectralGate.ps1` builds this single component without FFT, DCT, signal wrapper or SDK builds. Its 2,400 new cases cover five N values, ten controls (Int32.MinValue, -1, 0, 99, 100, 101, 199, 200, 201, Int32.MaxValue), both enable states, six band patterns and four spectrum patterns including signed zero and denormals. Equal-threshold, above-threshold, negative bands, zero denominators, and exact no-op paths are included. The real original CPU records every output bit and HRESULT and verifies complete core/state/channel/parameter/band contents plus guards; isolated Debug/Release candidates must match. Eleven separate safety refusals require the spectrum to remain intact.

Evidence directory: `xma-spectral-gate-validation`. Receipts pin source commit, run ID/attempt, original DLL SHA256 `a14d15addef502c2df6f6ba272d6098c4c131fbea9c3ed0149c11c4556347139`, and physical x87 CW027f with restoration. Candidates check that the original DLL is absent both on disk and as a loaded module. Actual Windows CPU acceptance passed at source `5bc9328c415cf1ea0f57e65e0d28d6caaa703284`, Actions run `40237077516`: all 2,400 complete output/HRESULT/state comparisons matched in both Debug and Release, and all eleven separate safety refusals passed. Independent original-instruction/model checks also passed the same 2,400 input combinations; they are preliminary corroboration, not the acceptance oracle. This closes only the optional attenuation stage; analysis/quantization/entropy, initialization and the full encoding driver remain unrecovered (see [next entries](XmaAfterTransform.md)).
