# 当前任务时长规则

用户于 2026-10-27 要求每轮尽量推进约70分钟，覆盖此前2026-10-24的1小时约定。本规则覆盖旧文档中的约25、35和45分钟约定。

后续实现阶段按约70分钟的有效工作量组织，包含实现、Windows 构建、原 DLL 差分、适用的 SDK 集成验证、必要修复、提交和交接。继续遵守 EFFICIENCY.md 的整组实现、统一完整验证、每约10–15分钟保存有意义检查点和 SDK 降频规则。提前完成时继续相邻且有价值的工作，不空等、不重复无关检查凑时长；关键验证应取得结果后收尾。外部阻塞或上下文容量风险导致提前交接时说明具体原因。纯规划修改和问答无需人为延长。
