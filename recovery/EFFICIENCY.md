# 编译器恢复的额度优化规则

生效：2026-10-23。用户要求降低任务额度消耗，绝对不能降低正确性。优化对象为重复工作；不能承诺固定节省比例，也不能通过仓库修改重置账号额度。

## 读取与调查

1. 续接只先读根 AGENTS.md、RESUME.md 和本规则，确认远程分支头，再按本轮目标读取适用的目录指令、源码、测试和类型文档。历史 STATUS.md 仅在当前入口缺失信息、追查来源或结果冲突时按章节读取；不从头重复扫描全部历史。
2. 先用文件目录、rg 或 GitHub 定点读取定位方法，再读取方法体、调用者和必要依赖。大型反编译文件按方法分段；行号只作导航，仍须核对方法名、布局、默认值、符号/枚举、指针偏移及平台分支。遇到未知依赖必须扩展调查，不能以节省额度为由跳过。
3. 同一会话已读取且未变化的内容不重复下载。批量读取独立文件，工具结果只显示所需字段与片段，避免目录元数据、完整成功日志和重复大段输出进入上下文。失败时读取足以定位原因的日志，必要时扩展到完整日志。
4. 已证实结论复用其来源与适用范围；新结论在对应类型文档记录原方法、源文件/提交、关键偏移、差分测试入口和未解决问题。原始证据或相关输入变化、证据缺失、结论冲突时重新核对，不能把旧总结当作原始证据。

## 实现与验证

- 同一依赖组的字段/类型一次实现、一次提交有效批次；不把每个字段切成独立规划、验证和交接。不因赶时长省略调查、修复或检查。
- 本地定向检查用于快速定位；提交阶段继续执行受影响组件原有的完整验证矩阵。Weapon 保留 /Od、/O2、四个平台（含 unknown 99）、ProcessInstance 三缓冲区逐字节比较、边界输入、显式拒绝及相应枚举回归。不能减样本、删断言、放宽比较或用抽样代替原有覆盖。
- 修改共用解析、重定位、桥接、枚举或资源逻辑时，必须评估所有使用者并运行受影响的回归；影响范围不确定就扩大验证，不能机械限定在文件名前缀。
- 真实 SDK 验证继续按已批准的字段/类型批次执行。Weapon 当前使用提交消息 [sdk-probe]；不要为每个字段重复触发。插件路由、TypeId/预处理、SDK 输入或集成路径发生改变，以及正式替换/宣称支持前，须完成相应真实 SDK 验证。组件成功不能冒充 SDK 成功，未进入 SDK 批次的类型继续标明未集成验证。
- 同一源码、测试、原 DLL、配置及工具链未变化且已有可追溯成功结果时，复用结果，不人为重复触发相同工作流。任何相关输入变化或影响范围不明均不能照搬旧成功；不能把旧 sourceCommit 的结果标为新代码已验证。环境性失败先核实原因；有理由重试时只重试必要任务，真实失败不得靠重复运行掩盖。
- Actions 先查 run 状态和失败步骤，成功通常只读结构化证据；有问题再取对应日志。不高频轮询，不为等待构建额外分析同一段代码。最终声明验证完成前仍须取得终态并核对 sourceCommit、runId、矩阵和比较结果。
- 本次只调整工作规则，不修改工作流触发器、测试或缓存。今后如要引入缓存，必须先证明缓存键覆盖相关输入并验证失效与冷构建；缓存不能替代差分测试。不要通过关闭自动回归或取消尚无替代结果的运行来省额度。

## 提交与交接

默认由单代理完成；已有明确并行代理要求时按要求执行。约 35 分钟有效实现阶段及及时交接规则继续适用，不空等、不重复检查凑时长。纯问答与规则修改不延长。

RESUME.md 保持为当前状态入口，记录本轮结果、精确验证锚点、尚未验证范围、下一组任务和必要路径。细节放类型文档，历史放 STATUS.md，不在多份交接中复制整段历史。不得为了压缩文本丢失会影响正确性的限制。

只修改说明文档时检查差异、链接、规则一致性和分支并发；无需为了文档修改额外触发 Windows/SDK 编译。提交前重新核对远程头，保留并发代码和 Actions 证据，普通快进推送，禁止强推。
