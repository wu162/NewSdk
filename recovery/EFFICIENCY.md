# 编译器工作规则

更新：2026-10-27。**效率优先，正确性是底线；以完成可用功能为主线。** 历史说明留在 git，不在本页累加。

## 功能推进

1. 明确当前阻塞能力、实现入口和完成条件，随后直接编码；已有证据足够时不重做全局规划。当前任务和下一步以对应交接入口为准。
2. 已知行为成组实现并接入生产，测试同步准备；未知点用最小探针查清，同时推进不依赖它的部分。调查只解决具体阻塞，不反复扩展已通过的路径审查。
3. 工具、审查和文档只用于解除当前阻塞或有依据地减少剩余工作，优先复用现有工具；不能用未接入抽象、准备工作或工具数量代替功能完成。
4. 默认单代理；用户授权并行时，分工优先覆盖实现、集成和真实用例，避免重复调查。主代理持续集成，不只协调汇报。
5. 按本轮用户时限推进，缺省约定见 STAGE_DURATION.md。一组完成后保存并继续下一项已授权且依赖满足的工作；不为凑时长制造任务。纯问答和规则修改完成即可收尾。

## 验证与复用

- 先做廉价预检：实际配置/fixture 字节、替换 token、所需等长/mtime 条件、Schema、脚本语法及控制器合同。缺本地工具时，将轻量检查放在 Windows 长编译/链接之前，不冒称已执行。
- 完整能力组准备好后统一验证。独立进程与隔离目录的组集中收集失败，任一失败仍拒绝整组验收；公共二进制身份、共享输入或环境损坏时停止依赖组。失败集中修复，不靠盲目重试掩盖。
- 保留原 DLL 语义、原始字节差分、拒绝行为、缓存冷热/失效、失败取消及适用 SDK 门槛；保留既有适用的 /Od、/O2、四平台含99、三缓冲区和 ABI 矩阵，不删样本或放宽断言换通过。
- 只改测试/控制器/文档时，优先核对并复用二进制：生产源码、实际依赖闭包、SDK/Schema/配置、生成代码、编译链接参数及工具链输入须未变，且来源与产物可核验。修改后的测试仍需新结果；生产输入改变则成批重建并跑完整受影响回归，影响不明时扩大范围。
- 复用校验 sourceCommit/runId、原始归档/运行文件哈希和成功范围，分别记录二进制与测试来源。失败运行仅可复用其中独立成功且未受失败影响的范围；失败组须修复重验，原终态保留。缺失、不完整或非祖先证据不得用于跳过验证。
- 不重复运行输入未变且证据有效的组；不关闭原有回归、不用 skip-ci、不取消尚无替代成功结果的运行。缓存须先证明键覆盖和失效，不能代替差分验证。

## 真实 SDK 验证降频与精简输入

- 按较大里程碑集中运行 SDK，不随每个字段或普通提交重复启动。路由、TypeId/预处理或输入链改变，可累计实现，但正式启用或宣称集成通过前须完成相应 SDK 验收；已知集成失败及时处理。
- 可在临时 SDK/MOD 副本精简无关输入，保留必要依赖，原版与恢复版使用相同输入；不删待验证实现或断言，保留四输出及适用三缓冲区/无原 DLL 对照，记录输入指纹和精简范围。小样例不冒充完整 MOD；保留完整 mymod 里程碑验收。
- 现有显式触发：Weapon 用 [sdk-probe]/[sdk-plugin]，Armor 用 [sdk-armor] 或 workflow_dispatch；标记须与实际监听路径变更对应。文档提交或组件通过不能代替 SDK 成功。
- XML 使用 SelectXmlComponentGroups.py 按源码及递归实际依赖选择受影响组，保留祖先成功证据和每组完整矩阵；删除依赖也须检查。联合 DLL 输入变化时重建，预检全部公开路由，仅对选中根执行完整 smoke，并区分 fullMetadataRoutes 与 testedTypes/testedRootNames；未选根不能冒充已重测。

## 执行、保存与交接

- 仓库访问用 GitHub 插件，不重复尝试 clone/认证排查。先读 AGENTS.md、对应续接入口和远程头；按阻塞读1–3个相关文件，定点搜索优先 rg，不默认展开全历史。
- 工具发现和返回先筛选，不打印整份注册表、目录树或成功日志。通常输出控制在150行/8KB内；必要证据分段完整读取，不能静默截断。先查 Actions 状态/失败步骤，异常再取对应日志。
- 一次启动持续跟进，等待 Actions 时先推进独立工作；没有独立工作可合理等待，低频查询直到终态，不让用户反复启动。不得把运行中写成通过。
- 首个可复现进展及时提交，长任务每约10–15分钟保存有意义检查点，注明未验证/验证中/已验证及下一步。普通推送、保留并发提交；禁止强推，合入遵循 AGENTS.md 的 PR 和用户批准规则。
- 续接入口保持简短，细节进对应能力文档，历史留 git。交接在对话中直接说明新增可用功能、真正阻塞及下一步；分别标明组件/SDK、复用/新验收，不以断言数或提交数代替功能产出。
- 仅文档修改检查差异、引用和并发，不触发 Windows/SDK 构建。没有可比计量就不量化额度或速度收益；估时区分实现、构建等待和失败修复。
