# 编译器工作规则

更新：2026-10-28。**效率优先，正确性是底线。** 本页只保留执行规则；当前任务见 [交接](REFACTOR_RESUME.md)，技术合同按需查 [实施计划](docs/CACHE_PARALLEL_PLAN.md)，历史留 git。

## 续接与功能推进

1. 先读 `AGENTS.md`、简短交接及本页，核对远程分支头；再按交接链接读当前任务的计划章节、1–3个源码入口和必要证据。日常续接不默认通读完整计划、能力流水或历史资料；首次接手或整体方向调整时再通读计划。
2. 明确阻塞、实现入口和完成条件后直接编码。已知行为按完整能力组接入生产，同时准备必要回归；未知行为只做定向探针。工具、调查和审查须服务当前交付，不重做全局规划或已通过的路径审查。
3. 默认单代理；用户授权并行后按实现、集成、真实用例分工，主代理持续集成。按当轮时限及 [STAGE_DURATION](STAGE_DURATION.md) 推进，一组完成后保存并继续已授权、依赖满足的下一项；纯问答和文档规则修订完成即可收尾，不凑时长。
4. 仓库访问用 GitHub 插件，不反复 clone/排查认证。文件定点搜索优先 rg；工具和返回先筛选，通常控制在150行/8KB内。必要证据分段读完，不静默截断；Actions先查状态/失败步骤，再取相关日志。

## 验证批次与触发决策

编译与测试全部在 GitHub Actions 执行；静态阅读、差异和引用检查不等于运行测试。

| 本批变化 | 应执行的验证 |
| --- | --- |
| 仅文档 | 检查差异、引用和远程并发；不构建 |
| 仅测试/控制器 | 优先复用符合下节条件的二进制，在CI重跑受影响测试 |
| 生产闭包变化 | 成组重建，执行受影响完整矩阵；影响不明时扩大范围 |
| 证据缺失或复用入口不适用 | 先评估现有工具的最小适配；无法可靠核验或适配成本更高时，说明缺口并集中重建一次 |
| SDK/大型MOD | 按下文适用里程碑低频集中执行 |

实现开始时列齐本能力组的必要覆盖，代码与测试一起准备。CI长编译/链接前检查真实Schema、必需字段、配置/fixture字节、变更token、等长mtime条件、脚本语法与控制器合同。按Debug/Release实际复杂度选择足以验证性质的负载；极端压力须另有目的。

保存检查点不自动触发完整构建。触发前核对push过滤、事件、ref/SHA、参数及监听路径；提交标记或推送成功不代表已触发。额外完整构建须说明生产变化、证据缺口或真实失败等原因，不能因HEAD变化或零散补测试反复重编。

独立进程/隔离目录的验证组集中收集失败，任一失败仍拒绝整组验收；公共二进制身份、共享输入或环境损坏时停止依赖组。真实生产错误及时处理，失败集中修复，不盲目重试。运行期间推进独立工作；无独立工作时可低频等待，持续跟进到终态，不让用户反复启动任务。

## 证据复用与正确性底线

复用前核验生产源码及实际依赖闭包、SDK/Schema/配置、生成代码、编译链接参数和工具链均未变；校验sourceCommit/runId、成功范围、原始归档及运行文件哈希。分别记录 `binarySourceCommit` 与 `testSourceCommit`，不强求二者等于HEAD，不删除来源校验来强行复用。修改后的测试必须取得新结果；缺失、不完整或非祖先证据不能用于跳过验证。

失败运行只可复用其中独立成功且不受失败影响的范围；失败组修复重验，失败/取消原终态保留。输入未变且证据有效的组不重复运行；不关闭回归、不用skip-ci、不取消尚无替代成功结果的运行。不能长期以“暂无复用入口”为由每次全量重编。

必须保留适用的原DLL语义、原始字节差分、拒绝行为、冷热/失效、取消/异常安全汇合、发布/缓存回滚、SDK及独立发行门槛，以及 /Od、/O2、四平台含99、三缓冲区和ABI矩阵；不删必要样本、放宽断言或超时换通过。缓存须证明键覆盖和失效；真实并行须证明后端调用区间重叠，sleep、排队数或超时强杀不能冒充并行/取消成功。

## 真实 SDK 验证降频与精简输入

按生产路由、TypeId/预处理、输入链等正式启用里程碑集中验收，不随字段或普通提交重跑；已知集成失败及时处理。可在临时SDK/MOD副本精简无关输入，保留依赖、待验证实现和断言，原/恢复版使用相同输入；记录输入指纹和精简范围，保留四输出、适用三缓冲/无原DLL对照及完整mymod里程碑，小样例不冒充完整MOD。

组件变化时按实际工作流核对显式触发：Weapon的 `[sdk-probe]/[sdk-plugin]`、Armor的 `[sdk-armor]` 或workflow_dispatch须匹配监听条件。XML用 `SelectXmlComponentGroups.py` 按递归实际依赖选受影响组（含删除依赖），保留有效祖先证据和每组完整矩阵；联合DLL输入变化须重建。预检全部公开路由、对选中根完整smoke，区分 `fullMetadataRoutes` 与 `testedTypes/testedRootNames`，未选根不称已重测。

大型MOD仅在专用测试分支显式低频集中执行：先做输入/Schema/路由/plan预检，严格复用已成功且匹配的二进制；首个真实baseline失败即保存诊断、停止后续大MOD。不存在的可选搜索路径遵循resolver语义，有界缓存不强求large hot全命中。准备、CLI与输出/归档成本分开记录。

## XML 并行认证（仅修改资格时读取）

按完整后端模块及共同读写/分配合同成组审计：独占树/namespace/引用、局部Builder/Tracker、const或受保护初始化表、真实外读/诊断/全局注册及数字驱动展开。使用显式闭合模块表，未知type保持owner，不用“全XML减黑名单”自动放行。

复用一套全路由四平台worker/owner三缓冲或准确拒绝矩阵，结合已有复杂原DLL差分和生产用例；不逐类型复制fixture或逐小组全构建。最小DOM通过不代表复杂字段、SDK全局可达或每类型双同类重叠；有效祖先语义证据按复用规则使用，未知行为才加探针，完整模块批次统一验收。

## 保存、计量与交接

首个可复现进展及时提交；长任务每约10–15分钟检查并保存有意义的未推送成果，尤其在长验证或复杂调查前。注明未验证/验证中/已验证及下一步，普通推送并保留并发提交；禁止强推，合入遵循AGENTS的PR及用户批准规则。

交接只保留最新有效来源、真实阻塞与下一步，附当前任务所需计划章节链接；细节放能力文档/证据JSON，历史留git。在对话中说明新增能力、验证范围和下一步，区分组件/SDK、复用/新验收，不用提交数、断言数或准备工作代替交付。

性能依据端到端耗时、真实后端调用和hash/read/copy等成本判断；记录输入、参数、机器/OS缓存及计时嵌套边界，无可比条件不宣称倍率。估时区分实现、构建等待和失败修复。
