## 大批实现与统一验证（2026-10-23 用户确认）

用户指出 GameObject 根属性按 68→74→84→85→87 多批实现/验证过细。本节作为后续默认流程；检查点保存与完整验证分开安排，原 DLL 证据核对和验收标准保持不变。

1. **按完整能力定批次。** 根属性默认以该类型全部根属性为一批；子节点按共享依赖组成连贯组；模块/多态分支按完整功能组推进。不要把标量、枚举、资源、列表、位集分别当成必须独立跑全矩阵的阶段。约 45 分钟是有效工作量目标，不能用固定分钟数机械拆字段或省略验证。
2. **先调查关键公共契约，再连续实现。** 一次整理本批次的布局、缺省、Marshal/Tokenize/endian、分配/重定位与拒绝边界。未知行为用定向原版探针查清，并继续推进本批次其他已查明部分；能在本轮解决的未知项纳入同批，不因一个边界问题把已知字段拆成多个小批验证。真实阻塞需在交接中说明，未支持输入继续显式拒绝。
3. **测试随实现编写，完整矩阵统一运行。** 实现过程中使用必要的本地语法、构建、生成器一致性及定向检查，提前发现测试宿主、命名空间、换行指纹等工具问题。整批代码与测试准备好后，统一执行受影响组件的 /Od、/O2、四平台含 99、三缓冲区逐字节差分、独立布局及拒绝测试。不得以合批为由删样本、弱化断言或减少平台。
4. **集中处理失败。** 先区分构建/测试工具错误和恢复逻辑差异，读取能定位问题的日志，将本轮已定位的相关问题一起修正后再验证。必要的定向复验用于缩短定位；最终仍须取得修复后实际源码的完整受影响矩阵成功结果。不要为每修一个字段重复启动全部 Windows 作业，也不能靠重试掩盖真实失败。
5. **及时保存中断检查点。** 首个可复现进展及时提交/普通推送，每约 10–15 分钟检查未保存成果；注明未验证/验证中、范围及下一步，未完成成果不宣称支持。
6. **完整批次集中验收。** 准备好整批代码与测试后，统一运行全部受影响回归；同一源码、测试、原 DLL 和工具链不变时，不重复运行相同完整 Windows 矩阵。最终证据须对应实际待验收源码；保留并发提交和 Actions 证据，禁止强推。该安排不关闭工作流、不使用 skip-ci、不取消没有替代成功结果的回归，也不允许绕过最终验收。
7. **SDK 继续按更大里程碑集中运行。** 组件批次可跨阶段累计；路由、预处理及正式启用等集成门槛继续遵循下节。组件成功不能冒充 SDK 成功。
8. **交接以完整批次为单位。** 只记录本批最终支持范围、sourceCommit/runId、完整矩阵结果、真实阻塞及下一能力组。历史失败保留在提交/运行记录；不把“新增工具失败”当作必须拆小恢复批次的理由。规则修订本身不能证明额度已降低。

## 实现与验证

- 按上节的完整能力组连续实现、统一验证；检查点可以多次保存，不把每个字段或表示类型切成独立规划、全量验证和交接。不因赶时长省略调查、修复或检查。
- 本地定向检查用于快速定位；完整实现批次准备好后继续执行受影响组件原有的完整验证矩阵。Weapon 保留 /Od、/O2、四个平台（含 unknown 99）、ProcessInstance 三缓冲区逐字节比较、边界输入、显式拒绝及相应枚举回归。不能减样本、删断言、放宽比较或用抽样代替原有覆盖。
- 修改共用解析、重定位、桥接、枚举或资源逻辑时，必须评估所有使用者并运行受影响的回归；影响范围不确定就扩大验证，不能机械限定在文件名前缀。
- 真实 SDK 验证继续按已批准的字段/类型批次执行。Weapon 使用提交消息 [sdk-probe]（原路由 payload）或 [sdk-plugin]（正式插件对照）；Armor 使用 [sdk-armor]。不要为每个字段重复触发。插件路由、TypeId/预处理、SDK 输入或集成路径发生改变，以及正式替换/宣称支持前，须完成相应真实 SDK 验证。组件成功不能冒充 SDK 成功，未进入 SDK 批次的类型继续标明未集成验证。
- 同一源码、测试、原 DLL、配置及工具链未变化且已有可追溯成功结果时，复用结果，不人为重复触发相同工作流。任何相关输入变化或影响范围不明均不能照搬旧成功；不能把旧 sourceCommit 的结果标为新代码已验证。环境性失败先核实原因；有理由重试时只重试必要任务，真实失败不得靠重复运行掩盖。
- Actions 先查 run 状态和失败步骤，成功通常只读结构化证据；有问题再取对应日志。不高频轮询，不为等待构建额外分析同一段代码。最终声明验证完成前仍须取得终态并核对 sourceCommit、runId、矩阵和比较结果。
- 此前那次规则修订只调整说明，未修改工作流触发器、测试或缓存；后续 SDK 触发策略以用户最新补充及下节为准。今后如要引入缓存，必须先证明缓存键覆盖相关输入并验证失效与冷构建；缓存不能替代差分测试。不要通过关闭自动回归或取消尚无替代结果的运行来省额度。
