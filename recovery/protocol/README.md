# Build information protocol 1.0 (P2)

`NewModCompiler plan --mod <directory> --sdk-root <directory> --out <directory>` discovers selected stream roots and writes UTF-8 `build.log`, `build.events.jsonl`, and `build-report.json`. `--events`, `--report`, and `--log` override their paths. Diagnostics use stderr. `--events -` is rejected pending verified native output isolation.

P2 adds an application skeleton, not a working asset compiler. `build` fails with `BACKEND_NOT_INTEGRATED` (exit 3) until an in-process `IStreamCompiler` implementation is installed. `doctor` reports the same limitation. A successful `plan` report states `PlanOnly` and `NoCompilationRequested`; it never claims assets were compiled. Controlled tests inject a test-only executor which is not shipped in the production app.

The standalone net48 x86 App project is a validation entry. App sources have no dependency on a recovered business DLL and can be inputs to the unified module build. Build with `recovery/scripts/BuildApp.ps1`; test Debug and Release with `TestApp.ps1`. Both use VS Roslyn and the .NET Framework 4.8 reference assemblies, without downloading packages.

## Paths, parameters, and plan

`--mod` must be an existing directory, including SDK-external directories and names containing spaces or Unicode. `--sdk-root` is independent. `--out` or `/od` is required and may not overlap either source tree. Diagnostic files must be distinct and must not reside inside source trees. Paths are resolved once against the invocation directory; the app does not change the current directory. `Data/Mod.xml` is required when base is selected. apt discovers `Data/AptUI/*.xml`; maps discovers `Data/AdditionalMaps/MapMetaData_*.xml`. Empty optional selections are recorded as `SkippedNoInputs`. Sorting and task IDs are deterministic and case-insensitive output collisions fail. XML Include/reference closure belongs to Core within each stream; P2 does not pretend to resolve it or invent cross-stream dependencies.

`newmodcompiler.json` in the MOD root optionally sets `package-content`, `package-format`, and `tp` using string values. Command-line options override project values; project values override defaults. Defaults are `base,apt,maps`, `loose`, and `Win32`. Unsupported formats and platforms fail during parsing. Repeated command-line aliases with conflicting values fail. Known legacy fields are preserved separately in `BuildRequest.Options`, with their source, for backend validation. In particular `/pc` is precompiled input, `/csc` is compression, and `/sc` and `/bc` are independent cache settings. Preservation is not a claim that the P2 skeleton implements cache or legacy output behavior. `/gui`, `/res`, `/pers`, `/mp`, `/poe`, `/sf`, and `/sh` are explicitly rejected. Unknown options fail.

## Event and report contract

Every event includes schemaVersion, buildId, increasing sequence, ISO UTC timestamp, monotonic elapsedMs, eventType, and level. Optional streamId/stageId/diagnosticCode/message/payload provide context. A single synchronous dispatcher writes complete JSONL lines and flushes them. Consumers ignore unknown optional fields in a matching major protocol version. Breaking changes increment the major version.

A normal controlled session emits exactly one final `BuildFinished`. A forced process termination or native crash may omit it. Callers must verify the report buildId and status, final event, and process exit code together; missing or contradictory evidence cannot mean success. Report replacement uses a flushed same-directory temporary file and atomic rename/replace. Previous reports are removed before work starts. Required sink/report failures return 7; if an output channel is itself broken, a complete final event/report cannot be guaranteed. The remaining channels are attempted and never justify success on their own.

Compile tasks execute sequentially through one owned `IStreamCompiler` in one process. Each receives a new StreamContext and an isolated `.build/<buildId>/<content>/<stream>` directory. Returned artifacts must exist within that stream workspace; sizes and SHA-256 are recorded from actual files, rather than trusting a provider. The provider is disposed on every controlled path. Cancellation uses CancellationToken at safe boundaries, without Thread.Abort. On cancellation/failure only the current build workspace is removed, and its artifact list is cleared. P2 does not publish staging files as a release; final output promotion and real backend lifecycle acceptance remain P4/P5 work.

Exit codes: 0 success (including plan only), 2 arguments/plan, 3 missing environment/backend, 4 compilation/input, 5 internal exception, 6 cancellation, 7 required diagnostic/report/output failure. Diagnostic codes are stable machine identifiers; callers must not parse translated message text. Parse errors before a valid output configuration are reported on stderr with a nonzero exit code; no session is claimed in that case.
