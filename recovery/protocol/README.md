# Build information protocol 1.0 (P2)

Artifacts identify the current completed output by path, kind and length. The compiler no longer hashes complete output files or records publication receipts. Byte comparisons belong to external validation.

`NewModCompiler plan --mod <directory> --sdk-root <directory> --out <directory>` discovers selected stream roots and writes UTF-8 `build.log`, `build.events.jsonl`, and `build-report.json`. `--events`, `--report`, and `--log` override their paths. Diagnostics use stderr. `--events -` is rejected pending verified native output isolation.

The standalone App entry has no asset backend and rejects `build` with `BACKEND_NOT_INTEGRATED` (exit 3). The unified production EXE integrates the experimental Win32 loose Core backend (caching disabled unless `/bc:true` is requested). A successful `plan` report states `PlanOnly` and `NoCompilationRequested`. Controlled App tests inject an executor which is not shipped in production; actual Core and CLI acceptance remain separate evidence.

The standalone net48 x86 App project is a validation entry. App sources have no dependency on a recovered business DLL and can be inputs to the unified module build. Build with `recovery/scripts/BuildApp.ps1`; test Debug and Release with `TestApp.ps1`. Both use VS Roslyn and the .NET Framework 4.8 reference assemblies, without downloading packages.

## Paths, parameters, and plan

`--mod` must be an existing directory, including SDK-external directories and names containing spaces or Unicode. `--sdk-root` is independent. `--out` or `/od` is required and may not overlap either source tree. Diagnostic files must be distinct and must not reside inside source trees. CLI paths are resolved once against the invocation directory; project sdk-root/out paths are relative to the MOD directory; the app does not change the current directory. `Data/Mod.xml` is required when base is explicitly selected. apt discovers `Data/AptUI/*.xml`; maps discovers `Data/AdditionalMaps/MapMetaData_*.xml`. Empty optional selections are recorded as `SkippedNoInputs`. Sorting and task IDs are deterministic and case-insensitive output collisions fail. The default plan explicitly reports `PlanKind: StreamDiscovery`. XML Include/reference closure belongs to Core within each stream; P2 does not pretend to resolve it or invent cross-stream dependencies. An optional `IDependencyPlanner` may supply an explicit stream dependency graph; the application deduplicates identical tasks, orders dependencies before consumers, and rejects cycles, missing inputs, unknown dependencies, or conflicting task/output identities.

`newmodcompiler.json` in the MOD root accepts profile, SDK/output paths, content/format, package identity, Additional/neutral flags, tp, and ss/pc/slowclean. Values use the existing scalar conversion (including numeric versions); boolean options accept booleans or true/false strings. Command-line options override project values; project values override defaults. Defaults are automatic input discovery (`auto`), `big` with Additional, and `Win32`. `--profile development` defaults to loose; explicit formats/selections retain their behavior. Automatic discovery without valid streams fails with PLAN_NO_INPUTS. `global-metadata` is the public selection name; legacy `maps` and internal maps task IDs/content/workspace names remain compatible. Unsupported formats and platforms fail during parsing. Repeated command-line aliases with conflicting values fail. Legacy `/art`, `/audio`, `/data`, `/dr`, schema, intermediate and cache paths retain their original strings and order for Core to resolve using its DataRoot/configuration semantics; they are not flattened into invocation-relative search paths. The production input-root candidate accepts `/dr`, `/data`, `/art`, and `/audio`: explicit search strings replace the corresponding MOD-prepended SDK defaults, retain semicolon order and the `*` document-relative wildcard, and are resolved by SettingsLoader after installing that stream’s DataRoot. A relative `/dr` is resolved from the SDK tools directory. These source changes require their own Windows/original-baseline acceptance. `/oix` and `/mr` are booleans, `/tl` is 0..9, and `/el` is 0..1, matching recovered Settings. Known legacy fields are preserved separately in `BuildRequest.Options`, with their source, for backend validation. In particular `/pc` is precompiled input, `/csc` is compression, and `/sc` and `/bc` are independent cache settings. Preservation is not a claim that the P2 skeleton implements cache or legacy output behavior. `/gui`, `/res`, `/pers`, `/mp`, `/poe`, `/sf`, and `/sh` are explicitly rejected. Unknown options fail.

## Event and report contract

Every event includes schemaVersion, buildId, increasing sequence, ISO UTC timestamp, monotonic elapsedMs, eventType, and level. Optional streamId/stageId/diagnosticCode/message/payload provide context. A single synchronous dispatcher writes complete JSONL lines and flushes them. Consumers ignore unknown optional fields in a matching major protocol version. Breaking changes increment the major version.

A normal controlled session emits exactly one final `BuildFinished`. A forced process termination or native crash may omit it. Callers must verify the report buildId and status, final event, and process exit code together; missing or contradictory evidence cannot mean success. Report replacement uses a flushed same-directory temporary file and atomic rename/replace. Previous reports are removed before work starts. The text log is optional; its failure disables that sink. Required JSONL/report failures return 7; if an output channel is itself broken, a complete final event/report cannot be guaranteed. The remaining channels are attempted and never justify success on their own.

Compile tasks run through one owned `IStreamCompiler` in one process. Each receives `StreamContext.OutputDirectory` under `OutputRoot/published/<content>/<stream>`. Core retains its real streams there and reuses complete four-file groups using the original manifest and linked checksums. The provider is disposed on every controlled path. Cancellation uses safe boundaries without Thread.Abort.

Only files explicitly completed by Core in this invocation enter the artifact list and BIG. Unselected streams and stale files are never discovered by scanning the output root. Core cleans its own asset and CDATA directories; a failed stream invalidates only its touched four-file groups. The output root and unrelated files are preserved.

BIG/SKUDEF are written directly in `OutputRoot/published`, through the existing per-file temporary writer and replacement. No directory transaction, previous generation backup, publication deduplication or MOD rollback remains. `ArtifactProduced` and the report use the same final paths. `publicationStatus` is `PublishedDirectory` when this invocation generated accepted files, `NotPublished` for a failed or empty build, and `NoCompilationRequested` for planning. Existing files alone never imply successful output. A late report/event/sink failure still returns exit 7 and reports the error; completed files and useful BAB cache updates remain on disk.

The report is serialized once after the terminal event and sink disposal, so it includes required close failures. If this final report write fails, stderr and the process return value carry the output error; no second terminal event is emitted. The last cancellation checks are at compilation and packaging boundaries. Required output close failures may change the final return value and durable report after a terminal event. Diagnostic paths cannot overlap `published`. There is no whole-MOD transaction guarantee.
