本轮按用户要求比较原版 SDK 与 PR #48 新版，不是三路改造前后 CLI 对比。
[Windows 41290030687](https://github.com/wu162/NewSdk/actions/runs/41290030687)

`1b9da37a00beb639c8c56590417ef51bb210c3cb`。新版复用已验收 Release，未为本次计时重建。

原版由 15 次原 BAB 串行启动组成，新版是一个 jobs4 CLI；loose 输出包含报告和发布，未测 BIG/SKUDEF。
本轮衡量原 SDK 与当前整个实现的差异，不能把总提速单独归因于三组调度。

## 输入与运行身份

官方 7.1 源包 982,990,565 字节，MD5 `7baeedd038574044e977c6495564665a`，
SHA256 `0c59ed425b1ab55d926bfec858c6f60a0186a5d46e4cb5b295e42891a5ecdb41`。
解压后 13,391 文件、3,254,494,799 字节，完整保留原始贴图、音频和 89 个 Joypad 声明，
没有运行历史裁剪或 TGA 头规范化。两方共享同一份物理 MOD 输入和相同顺序的搜索根。
当前编译器已经支持这些 Joypad 类型，因此本轮输入与旧 89 项裁剪口径不同。

双方使用 MOD 自带的同一 runtime Schema overlay，仅替换 `AssetTypeLocomotorTemplate.xsd`
（SHA256 `2c04dc9b5d4f7724f3a5eb057715d2b988ac7dcec1c3b72508a89ee0d94db601`），结束后完整还原。
原 SDK 的 27 个 EXE/DLL 按固定原源 `39039961847cd1ca9cb93743fd51741a4e5c9f49`
逐一核对 Git blob；独立原 runtime 仅适配 CLR4 startup，assetbuilder 配置语义保持原样。
新版三个运行文件和整个生产/SDK/构建依赖闭包与已验收 1b9da37 核对一致。
原/新缓存分别存放，冷命名空间起初不存在；源码、SDK、运行文件和搜索根存在性审计均通过。

## 输出与失败边界

整体工作流为 **failure**，不是全输出等价或完整热缓存验收通过：

- 冷态只有 `base/mod/mod.bin` 不同，其余 4057 个成员的长度和 SHA256 一致。
- 归档内 60 个四流由独立工具直接比较，59 个原字节相同；全部 15 个 manifest、imp/relo 相同。
  基础流两侧均 17,801 个资产，没有新增/缺失或元数据差异。
- 330 个不同资产全部是 Texture 的 DXT1/BC1 负载，根与 128 字节 DDS 头一致，
  共 59,793,151 个不同字节。名称集合与历史 330 项一致；其中 20 个 Player* 纹理的原 SDK
  chunk SHA 与历史变化，新版所有 330 项 SHA 均与历史一致，其余 310 项两侧身份及差异计数相同。
  这 20 项变化原因未确定，不宣称差异字节完全复现历史。
- 3,998 个 CDATA 核对的是完整输出库存的长度/SHA256。归档有意只保存四流；
  不将 60 个链接文件的本地原字节复核冒充全部 CDATA 的独立原字节复比。
- 新版热态在 `base/Mod` 的 `AlliedLegionnaireInfantry → BaseInfantry` 继承处理中报告
  source XML missing，exit 4、0 个发布产物。属于此前登记的完整 MOD 热继承失败同类边界；
  原 SDK 热态仍独立执行并成功，2.490 秒不参与热态性能比。

## 资源记录的解释

CPU/IO 峰值均为 4。全程 `peakRetainedResultBytes=942,551,200`，
最后一次动态采样 `byteBudget=298,629,120`，两者不在同一时刻，不能直接判断峰值时的并发预算违规。
记账值含保守工作集估算，不是进程实际内存；实际工作集另见上表。

现有实现允许全局记账为零时放行单项大任务，结果实际增长回记也不重新做预算准入；
FLA 预展开另有跳过初始准入的路径。因此这是软准入与回记，不能称为严格全程内存硬上限验收。
现有 performance=off 证据不足以把本次峰值归因到某个资产或唯一代码分支；
进一步定位需要预算/峰值的同步时间、流/资产身份、记账原因与活跃资源时间线。
本轮未为性能比较修改生产实现或放宽输出门槛。
