# 热缓存慢于无缓存：执行方案

更新：2026-10-28。所属：[实施计划B组](CACHE_PARALLEL_PLAN.md#plan-b)；状态：[当前交接](../REFACTOR_RESUME.md)。执行与Actions验收遵循 [EFFICIENCY](../EFFICIENCY.md)。

**按用户本轮要求调整方向：借鉴老SDK的会话状态与资产文件缓存，主线改为依赖清单 → 文档状态复用 → stream复用，并将文件格式、体积和读写放大纳入验收。以下均为待实现设计，不是生产能力或性能收益声明。** 原先“先优化全根枚举，再并行鲜读”降为局部优化，不再是结构改造的前置条件。

## 基线与老SDK参考

最新小mymod：binary `e86958de` / test `e5809d10` / [40693590489](https://github.com/wu162/NewSdk/actions/runs/40693590489)。Release无缓存760ms、三热中位2217ms，47hit/0miss/0backend，四输出原字节一致。首热另一次盘点1360.599ms（含受控读1007.240ms），恢复15.806ms、Key3.864ms。子阶段嵌套，不能与三热中位混合相减。最新缓存磁盘体积、文件数和解码内存尚无本轮测量，不推断压缩收益。

仓库Core中的SDK来源实现提供可复用入口（这些文件已有恢复/强化改动，不把现态全部当作原版行为）：

- [SessionCache.cs](../src/Managed/Core/BinaryAssetBuilder.Core/SessionCache.cs)：读取XML或XML.deflate，保存文件、文档状态和stream hints，检查上次记录的文件。
- [AssetDeclarationDocument.cs](../src/Managed/Core/BinaryAssetBuilder.Core/AssetDeclarationDocument.cs)：按文档、依赖、include路径、类型/插件身份以及define、继承变化决定重载。
- [DocumentProcessor.cs](../src/Managed/Core/BinaryAssetBuilder.Core/DocumentProcessor.cs)：复用未失效文档，具备StreamHints和已有stream加载路径。
- [BinaryAsset.cs](../src/Managed/Core/BinaryAssetBuilder.Core/BinaryAsset.cs)：已有资产文件与CDATA复用。新路径仍必须经动作身份授权，不恢复旧位置优先级绕过。

借鉴上述分层和失效机制，不直接启用旧session代替新缓存，不复制XML.deflate作为唯一新格式。旧 `/sc:true` 的兼容行为、并行拒绝及数据目录保持隔离。

## 实施顺序与行为合同

1. **依赖清单与读取闭包。** 在现有前端、resolver和后端读取边界记录实际文件内容身份、工具/config/schema、有效选项、候选路径顺序、未找到的候选以及会影响选择的目录成员。成功构建持久化清单，后续先验证清单；变化时重新发现受影响依赖。工具身份也应覆盖实际加载闭包，不能仅信任版本字符串。不能只使用ReferencedFiles或只记录成功打开的路径。
2. **文档状态复用。** 复用现有session状态结构和失效逻辑，持久化必要准备态、引用/define/继承依赖及必须重放的注册副作用；不保存整套运行时对象图。未变文档避免重复解析/准备，失效沿实际依赖传播；剩余任务继续使用现有ActionCache与有界执行器。缺失必须语义信息就正常重建，不跳过引用、schema等正确性约束。
3. **完整stream快路。** 输入闭包、链接选项与完整输出身份有效时，复用四输出及适用CDATA；只改包成员Additional时只更新受影响封装。必须先通过输出完整性、原字节和事务验证，才能称“仅重打包”。stream记录引用已有结果，避免无依据复制另一整套资产payload。

本轮计划明确接受的目标行为变化：**已证明无关的SDK根成员变化不再使新缓存路径失效；影响输入选择、语义或输出的变化仍必须失效。** 不再把“任意根成员变化都拒绝”当作新路径最终目标。闭包尚未覆盖的路径保留原全根保护或不启用相应快路，逐组认证后替换；不能未经证明直接删除扫描。旧session保护合同不改。

内容摘要必须对应实际消费的字节，采用冻结输入或经验证的受控读取/租约；发布前仍验证相关内容和解析决策有效。MOD/Additional在相关闭包内保持必要鲜读与变化保护，不凭mtime/size复用摘要。新增高优先级文件、原缺失路径出现、删除/换类型、根替换和目录枚举变化均须覆盖。现有build级512句柄租约已经存在，不重复实现或静默扩大预算。

## 与当前后端优化的衔接（实现前置合同）

本方案叠加在现有Prepare / Execute / Commit链和认证执行器上，不恢复老SDK串行编译循环，不以文档命中代替完整后端合同。资格以当前生产认证表为准，历史覆盖数量不作为新增类型自动准入规则。

| 衔接点 | 必须保留或重建的信息/行为 |
| --- | --- |
| 准备态与身份 | 持久状态包含后端实际消费的type/schema/namespace、有效属性、引用及局部槽位、兼容元数据、外读身份；重新生成独占PreparedAsset，不能只有OuterXml。ActionKey仍按实际工具/后端、参数、准备态与路径语义生成；缓存格式版本另列，不用旧TypeHash/FileBase取代强Key |
| 上下文与副作用 | TaskId、源位置/诊断归属、提交序号、worker、scratch、取消令牌和租约均在本次构建重建，不序列化进语义Key。保存/重放必要字符串哈希注册、允许的元数据变化及诊断语义；不因文档复用漏掉全局注册，不重放旧计时或线程身份 |
| 完整结果与owner提交 | 三缓冲区、全部CDATA及合法缺失状态、ResultDigest和兼容元数据不能为缩小文件而省略。动作命中仍经身份授权、私有staging安装、副作用应用、现有verifier和owner确定顺序提交；不能回到Output/Local/Cache优先级绕过 |
| 准入与内存 | CanCache、CanRunParallel、当前资源准入独立判断；读取旧记录不能授予worker资格。沿用MachineResources.v1和PreparedBytes的后端展开估算，索引常驻、解码缓冲、重建准备态、在途与待提交结果必须纳入预算核算，避免双计或漏计。压缩文件大小不能替代W3X帧/通道或Audio解码展开量 |
| 生命周期 | 恢复的文档进入同一跨文档任务队列；未提交任务完成前不能MakeComplete/MakeCacheable/保存文档或释放仍被继承使用的XML。未知/不安全owner调用保持屏障；取消停止派发、等待native返回并统一释放租约和解码缓冲 |
| 整stream命中 | 只有覆盖所有成员输入、输出、必要验证和副作用的独立认证才可跳过内部执行；不能借stream命中绕过不可缓存类型的真实执行/警告。未认证stream退回文档/动作层。stream复用单独计数，不伪造每资产ActionCache hit或后端区间 |

具体后端边界：

- **XML/APT：**保留显式模块认证表，重建独占DOM、namespace、引用/局部索引和真实外读；未知类型与TestTexture不自动开放。文档状态复用须证明与正常Prepare所得后端输入及拒绝语义一致。
- **W3X：**动画/网格冻结输入、独占native scratch/output、初始化/trace约束和按展开量估算预算继续有效。磁盘状态不保存native指针，不把低体积缓存当作低运行内存。
- **Audio：**保留实际编码器身份、输入持续租约/冻结版本、header和路径语义、完整CDATA、允许副作用；PcmWaveAudioCompiler、PCSampleRate、PathMusic及未闭合/警告路径沿现有条件处理，不扩大资格。
- **Texture及其他未知外读：**保持兼容owner和既有拒绝/屏障；文档或stream缓存不能成为隐式绕过入口。

新增验证必须同时覆盖：正常Prepare与恢复准备态等价、命中/冷miss混合的跨文档串并行原字节对照、乱序完成仍确定提交、恢复数据压力下worker降额/owner回退、取消/损坏回退后的租约释放，以及工具或认证变化使旧状态不能越权复用。保留无缓存或空store的真实后端调用重叠测试；热缓存零调用只能证明复用，不能证明后端并行或后端算法优化收益。恢复/解码计时与backendIntervals分开记录，沿用现有hit/miss/bypass计数合同；新文档/stream层计数单列。

## 文件格式与布局

目标是减少打开次数、解码分配和重写量，同时保持按需读取、损坏隔离和事务恢复。下列为首版设计方向，具体阈值由同一真实数据集对照后固定并记录，不先开发通用存储引擎。

| 层 | 首版格式与内容 | 体积与访问约束 |
| --- | --- | --- |
| 会话/依赖索引 | 显式版本化二进制表；路径/字符串表去重，文件、文档和stream用稳定ID关联；摘要存原始字节 | 启动只读取必需索引；不嵌入base64 payload或完整XML DOM；语义路径与物理路径不可混同 |
| 文档状态 | 独立可定位记录/块，保存复用所需的最小语义状态 | 同源且同配置身份一致才共享；不要每个stream复制完整依赖图；修改单文档不重写全部状态 |
| 动作结果 | 保留现有已验证payload语义及完整CDATA；manifest/索引记录偏移、长度、编码及摘要 | 大payload独立按需读取；小记录可按有界大小分片聚合，避免“一资产很多小文件” |
| stream结果 | 清单引用已确认输出及内容摘要 | 不无条件重复存储动作payload；需要独立副本时将空间与复制成本列入报告 |

二进制协议须明确magic、格式版本、字节序、字符串编码、记录数、偏移/长度、压缩标识、原始长度和完整性摘要；缓存格式版本与工具/语义版本分别校验。未知版本安全miss并重建，旧格式使用独立目录/版本，不原地覆盖旧session文件。解析先检查范围、整数溢出、数量/单条长度/总解码预算，拒绝截断、越界、非法路径及异常膨胀；校验索引与实际读取块，不因分块丢掉完整结果集合检查。

XML/JSON仅用于诊断导出或小型人工检查信息，不能让热路径每次反序列化整份大XML/JSON；不用依赖运行时对象布局的通用对象序列化。先复用现有二进制读写及运行时可用压缩能力，不为格式选型引入新数据库/第三方部署依赖。

### 压缩与文件数量

- 小索引优先不压缩；体积确实较大时比较不压缩与分块Deflate。大文档块/可压缩原始数据允许独立压缩；已压缩音频等payload默认不再压缩，除非端到端实测有收益。
- 记录每块编码、压缩前后长度和完整性身份；随机命中只解压需要的块。避免单个全局压缩包导致局部修改重写全包、热命中解压全库。
- 小文件聚合与独立文件做有限对照：文件数、打开次数、索引开销、磁盘实际占用、单改重写字节和损坏影响范围同时评估。聚合块有大小上限，冷写与修复按不可变分片/新代发布，不做原地破坏性更新。
- 压缩阈值、块大小、分片阈值须写入实现常量/格式合同和测试；先在已有小mymod与代表性W3X/Audio数据上选择，再低频用Upheaval确认。不预设“压得最小就是最快”。

### 容量与事务

分别约束store总字节/条目、单条解码上限、在途缓冲和句柄；拒绝/淘汰必须退化为正确重建。复用现有容量和清理机制，补齐索引引用关系：不能删掉仍被当前可见记录引用的数据。陈旧代、孤儿块、pending和替换备份计入峰值占用；清理由所有权/锁保护，不能删除另一构建在用的数据，不先做全局CAS或复杂GC。

索引和数据块作为同一代发布，沿用pending、私有staging、备份和回滚合同；任何可见索引不得指向尚未确认或缺失的payload。取消、报告/sink失败、磁盘空间不足、写入中断均不破坏旧已确认代。缓存与可写输出不能共享可变字节；容量治理不能削弱发布隔离。

## 集中验收与“解决”的判定

1. 扩展现有缓存/payload/Core/SDK入口，按上述三组实施并集中验收，不新建基准平台。依赖清单先覆盖等长等mtime、define/继承/include/schema、native读取、查找优先级/负依赖、输出缺失与损坏；新增“修改未消费的根成员不失效”和“新增高优先级资源必须失效”成对测试。未认证路径及旧session保持原拒绝行为。
2. 格式覆盖确定性往返、版本不匹配、截断/越界、错误摘要/长度、缺块、解压上限、聚合块局部更新、容量淘汰及崩溃恢复；与无缓存严格比较四输出、CDATA、BIG内容，保留取消/异常汇合、租约释放和事务回滚。
3. 同runner、输入、SDK、配置、jobs和输出布局下，比较无缓存、空store、全热、单文档/资产修改、Additional-only；无缓存/热缓存交替至少3对，保存中位数、范围及OS缓存条件。旧/新工具各自预热匹配store，不共用失配缓存。
4. 同时报告：索引/文档状态/payload/stream各自逻辑与落盘字节、总文件数、压缩率（注明分母）、热启动实际读取/解压字节、打开次数、反序列化时间与峰值内存、单改写入量、事务期间峰值磁盘占用，以及端到端时间、后端调用和实际并发。无法取得磁盘分配大小时明确只报告文件长度，不冒称实际占用。缺少数据标待测，不编造MB目标或收益比例。
5. “开销下降”与“解决倒挂”分别验收。后者要求指定样例热缓存稳定快于同配置无缓存、差异超过本轮波动，同时公开冷写/单改代价和缓存体积。小mymod先验收，稳定后低频复测完整Upheaval；不能用压缩率、零后端调用或单次最快替代净收益。

必要读取仍占主导时再做有界1/2/4 reader对照；owner维护非线程安全租约状态，reader独占SHA/缓冲/handle，并保持确定归并、预算与异常汇合。它是闭包内局部优化，不替代减少无关工作。
