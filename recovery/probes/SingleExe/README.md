# G1 unified-link probe

This is an isolated architecture probe, not a production compiler or SDK acceptance.
`BuildSingleExeProbe.ps1` builds C# Foundation and Application netmodules and real
C++/CLI/native objects, then passes all of them to MSVC `link.exe /LTCG`.
It does not use `/ASSEMBLYMODULE`, merge prebuilt DLLs, or extract DLL resources
at runtime.

On a VS 2022 x86 developer PowerShell:

```powershell
./recovery/scripts/TestSingleExeProbe.ps1 -OutputDirectory recovery/evidence/refactor/g1/local -Minimal
```

`-Minimal` uses the actual AssetBuffer class body and recovered Hash source. It
derives ArmorCompiler from its production source by replacing its Core import
with the Foundation module import, normalizing include paths, and excluding only
the higher-level `ProcessInstance` adapter whose declarations require full Core.
The complete `CompileXml` implementation and Native Armor/ScalarParsing/Relocation
sources remain the actual recovery implementations. Generated inputs and their
hashes are retained outside the runtime directory. Production sources are not
edited by this generator.

The host runs all 284 fixtures from the existing Armor fixture categories across
Win32, Xbox360, PlayStation3 and unknown 99 for component regression purposes;
this does not enable non-PC product support. It checks three byte buffers and
independent instance/relocation layout. Hash fixtures exercise all six overloads,
ANSI strings, high bytes, tail lengths, seeds and prefixes. The same 610 transcript
rows are generated by an isolated original host and by each Debug/Release EXE.
The probe also verifies an explicit null-node failure and EXE ownership of its
managed business types, one physical module, no old business AssemblyRef or
loaded assembly, and exact embedded resource bytes. Runtime tests quarantine
all input objects/netmodules and run from an EXE/config-only directory.

For full G1, supply a Foundation directory produced by
`BuildManagedFoundation.ps1`; omit `-Minimal`. The real full Armor bridge is then
used, `ManagedFoundationValidation.Run(true)` executes, all Foundation resources
are embedded and checked, and only the explicitly declared `antlr.runtime.dll`
is added. Full managed metadata validation, G2 and SDK acceptance each retain
separate evidence; a minimal-probe pass is never a full-G1 pass.

Reference: Microsoft Learn, [`.netmodule` files as linker input](https://learn.microsoft.com/en-us/cpp/build/reference/netmodule-files-as-linker-input?view=msvc-170).

The intermediate C# modules intentionally use `AnyCPU`; `link.exe /MACHINE:X86`
still fixes the final executable to x86. On the recorded VS 2022 toolchain,
`/platform:x86` module input fails with LNK1302, while the same real source using
AnyCPU modules passes Debug/Release linking and all 610 transcript rows. No
unsafe-code marker or IL safety flag is removed. See
`recovery/evidence/refactor/g1/link-route-decision.json` and the fixed run receipt.

To leave the tested EXEs available for the following G2 C step:

```powershell
./recovery/scripts/TestSingleExeProbe.ps1 -OutputDirectory recovery/evidence/refactor/g1/full-local -FoundationDirectory recovery/artifacts/refactor-foundation -BuildDirectory recovery/artifacts/refactor-link
# Reuses already-built Debug/Release Foundation modules. The following path is fixed:
# recovery/artifacts/refactor-link/Release/bin/NewModCompiler.exe
```
