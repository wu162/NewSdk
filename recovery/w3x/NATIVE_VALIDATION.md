# Native component verification

`TestW3xNative.ps1` builds x86 native `/Od` and `/O2` components and all independent algorithm/serialization test executables, then executes original-DLL differentials. It does not launch BAB, EALAModStudio or the SDK and does not enable the production plugin backend.

- `W3xNativeOracle.cpp` resolves original mesh-conversion metadata tokens `0x060000C2`–`0x060000C8` and `0x060000D2`. Reflection passes explicitly boxed native pointers to the actual original IL methods. All 160 destination bytes, including unwritten stride/padding/canaries, are compared, with separate original source-immutability and declared-width canary assertions. Inputs include IEEE edge bit patterns, the nonstandard half shift case `0x08800000`, deterministic random patterns, count zero, repeated/negative strides, unaligned addresses and both endians. CopyDirect Vector3 big-endian rejection is confirmed statically by original IL and tested on the recovered implementation; the differential does not invoke the original native C++ exception. Unsupported NaN/overflow conversion boundaries produce separately labelled original-only `PROBE` records and are excluded from accepted fixture totals.
- `W3xAnimationOracle.cs` invokes original `Plugin.ProcessInstance` and the recovered XML component bridge with the same already-preprocessed animation XML. It compares instance, relocation and import arrays byte for byte. The matrix covers empty channels, scalar/quaternion/mixed channels, first-frame offsets, BinaryMove, sign changes, platform compression defaults, explicit flags, error thresholds and reduction rates. Platform 99 is included only with explicit compression settings. BAB preprocessing is outside this component gate.
- `W3xAdaptiveDeltaOracle.cpp` compares original internal CompressFrame, including filter/quantized-frame/previous-value/error behavior, and full Compress/EstimateSize for source channel groups. `W3xMeshBuilderOracle.cpp` invokes original internal BuildVertexData and original Tracker finalization; its vertex-data chunk comparison does not claim full mesh ProcessInstance coverage.
- `W3xTimecodedOracle.cpp` compares original Compress/EstimateSize, retained frames, value bits, binary flags and source immutability; original WriteOut and original Tracker finalization are compared with encoded recovered chunks in both endian modes. Empty channels compare Compress/EstimateSize only because original WriteOut dereferences the absent first frame. This test deliberately exercises nonstandard scalar interpolation, quaternion sign changes, reduction and ushort timecode truncation.

The runner attempts all independently runnable groups in both optimization modes and writes `native-runs/<run>-<attempt>/validation.json`, including actual per-group status and failures. Any failed group still fails the overall workflow; the read-only workflow uploads its logs and validation. This session preserves the downloaded evidence in a unique immutable directory, and only an entirely successful matrix can be accepted. Failed logs/validation remain available too. Source code or independent tests alone do not establish original differential success. A remote successful run must still be tied to its actual `sourceCommit` before an acceptance claim.

## FinalizeTracker boundary

Original Plugin method `0x06000144` calls `Relo.Tracker.MakeRelocatable(tracker, chunk, helper, 0)`, copies exactly all three sized byte arrays and destroys temporary allocations. Original W3X MakeRelocatable body (`-Module-.cs` lines 2870–2990 at extraction run `40162934653-1`) matches shared `Relocation.cpp` serialization: contiguous allocation-order blocks, sorted pointer/reference bookmarks, pointer destination offsets, imported value plus one, conditional `0xffffffff` table terminators and platform-endian words. No shared implementation was modified.

The component animation serializer uses shared `Tracker.MakeRelocatable(bigEndian, 0)` directly. Its output is tested through the animation three-buffer differential; there is no claim that the recovered Tracker object has the original VC8 EASTL pointer ABI, nor that the public pointer-ABI FinalizeTracker method has been restored. A true pointer-ABI replacement remains a separate integration task. Complete mesh ProcessInstance output and SDK verification remain outside this workflow.
